# Mission 3 Reflection

Out of the three cloud platforms, I think Google Cloud Platform impressed 
me the most. I liked how straightforward its pricing felt compared to the 
other two, and learning that Google actually created Kubernetes made GCP 
feel like the platform built with developers in mind rather than pure 
enterprise sales. AWS was impressive too, mostly because of how massive 
its service catalog is, but that same size made it feel a bit overwhelming 
to explore compared to GCP.

Even though AWS, Azure, and GCP are competitors, going through this mission 
made it obvious how similar their core structures actually are. All three 
split their global infrastructure into regions and zones so applications 
can stay available even if one data center goes down. All three offer 
basically the same categories of services too — virtual machines, object 
storage, managed databases, and private networking — just under different 
names. And all three run on a pay-as-you-go pricing model managed through 
a web-based console, so the barrier to just trying them out is low.

What stood out most to me is that there isn't really a single "best" cloud 
platform — it completely depends on the business doing the choosing. When 
I worked through the client scenarios in Checkpoint 4, that became really 
clear. The university client made way more sense on Azure because they 
were already running Windows Server, Microsoft 365, and Active Directory, 
so migrating to Azure meant keeping most of their existing setup intact. 
Meanwhile the AI research company was a much better fit for GCP because 
of its strength in machine learning tools and Kubernetes support. Neither 
platform is "better" in general — they're just better for different jobs.

Doing this mission changed how I think about cloud computing a bit. Before 
this, I mostly thought of AWS as basically the default choice since it's 
usually the most talked-about platform. Now I get why a company would 
deliberately pick Azure or GCP instead, depending on what tools they 
already use or what kind of workload they're running. It made me think 
more like someone solving a client's actual problem instead of just 
picking whichever brand is the most popular.

This mission also helped grow my GitHub Cloud Computing Portfolio. I now 
have a set of well-organized, properly formatted Markdown files comparing 
real cloud services side by side, plus practice writing comparison tables 
and structuring documentation that I can reuse in future labs. It's a 
small but noticeable step toward having a portfolio that actually looks 
like something a cloud engineer would put together.
